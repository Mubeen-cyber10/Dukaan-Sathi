System Security Controls

Implemented (frontend demo) Planned (backend)

Role-Based Access Control (RBAC)

Implemented (frontend demo)

Roles partitioned into Shop Owner and Platform Super Admin. Guard script blocks cross-role navigation; sensitive functions verify caller permissions internally before execution.

Cryptographic Hash Chain Audit

Implemented (frontend demo)

All security actions linked into a forward-chained SHA-256 ledger using the Web Crypto API (`crypto.subtle`). Prevents retroactive modification and repudiation.

Data Minimization & Masking

Implemented (frontend demo)

Phone numbers masked (`0300-***-**45`) with 10-second auto-hiding owner reveal; CNIC numbers completely excluded; Super Admin partitioned from customer khata entries.

Defense-in-Depth & Idle Timeout

Implemented (frontend demo)

Strict Content Security Policy (CSP), HTTP security headers (nosniff, DENY frame), 5-failed-attempt login lockout, and 5-minute inactivity terminal timeout monitor.

Database Row-Level Security (RLS)

Planned (backend)

PostgreSQL Row-Level Security policies ensuring tenant separation at the query engine level, guaranteeing shopkeeper data partition even if application logic is breached.

Hardware Security Module (HSM) Key Management

Planned (backend)

Asymmetric signing keys stored inside FIPS 140-2 Level 3 HSM with automated cryptographic key rotation and non-exportable private root certificates.

Distributed Rate Limiter & Web Application Firewall

Planned (backend)

Edge Redis token-bucket rate limiting across API routes and WAF rules inspecting layer-7 HTTP payloads to block automated bots and credential stuffing.

Carrier-Integrated SMS/TOTP Gateway

Planned (backend)

Direct integration with local Pakistani telecom aggregators (Jazz, Telenor, Zong) for cryptographic time-based OTP delivery with anti-SIM-swap protection.

Security Proposal Threat Model & Mitigations (7 Threats)

Threat 1

Privilege Escalation & Unauthorized Shop Self-Approval

Vulnerability: A malicious or compromised shop owner attempts to approve their own business or access platform governance functions.

Mitigation: Separation of duties enforced. Guard script restricts routes, and sensitive functions (`approveShop`, `rejectShop`) independently check `currentUser.role === 'admin'` inside the function, logging denied attempts.
Threat 2

Credential Stuffing & Password Brute-Force Attacks

Vulnerability: Attackers run automated password spraying against shopkeeper emails to hijack retailer accounts.

Mitigation: Lockout engine disables the login form for 30 seconds after 5 failed attempts with a countdown timer; generic "Invalid credentials" error response prevents username enumeration; MFA step required.
Threat 3

Stored & Reflected Cross-Site Scripting (XSS)

Vulnerability: Malicious script payloads injected via customer names, khata notes, search queries, or shop details execute in peer or admin browsers.

Mitigation: Strict Content-Security-Policy (CSP) meta tags and headers; elimination of unsanitized innerHTML in favor of `textContent` and shared `escapeHtml()` output encoding.
Threat 4

Session Hijacking & Unattended Terminal Exploitation

Vulnerability: Shopkeepers walking away from shared counter computers leave active sessions vulnerable to unauthorized transaction manipulation.

Mitigation: 5-minute inactivity idle monitor triggers a 30-second warning countdown before auto-logout; sessionStorage isolation ensures credentials are never stored; `pageshow` back-button cache prevention.
Threat 5

Khata Ledger Repudiation & Historical Record Tampering

Vulnerability: Disputed transactions altered or deleted retroactively by rogue operators to conceal stolen inventory or fraudulent claims.

Mitigation: Strictly append-only khata architecture (no edit or delete controls); platform audit stream forward-chained using Web Crypto SHA-256 hashes with tamper-detection verification.
Threat 6

Customer PII Leakage & Insider Snooping

Vulnerability: Support or platform administrators accessing private customer phone numbers or customer financial debts.

Mitigation: Zero-knowledge admin partition: Super Admin interface never renders customer balances or khata entries; phone numbers masked (`0300-***-**45`) with 10s owner-only reveal audited in logs; CNIC numbers omitted.
Threat 7

CSV / Spreadsheet Formula Injection

Vulnerability: Customer names or notes prefixed with formula characters (`=`, `+`, `-`, `@`) executing arbitrary commands when exported and opened in Microsoft Excel.

Mitigation: Automated sanitization in `neutralizeCsvCell()` strips or prepends single-quotes to formula trigger characters before report CSV generation.
