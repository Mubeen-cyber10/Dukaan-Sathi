Security & Trust Architecture

Dukaan Saathi is engineered from the ground up with defensive software design patterns.

1. Multi-Tenant Data Isolation

Each shop operates within an isolated tenant partition. Access controls ensure zero cross-tenant leakage or data visibility between shopkeepers.

Tenant Partitioning

2. Append-Only Khata Integrity

Financial ledger entries cannot be edited or deleted by any user level. Historical credit records are immutable, preventing ledger tampering or disputes.

Immutable Ledger

3. Actor Audit Trail

Every transaction logs the exact timestamp, credit/payment delta, and actor identity (e.g. Shop Owner or Cashier) for total accountability.

Audit Logged

4. Multi-Factor Authentication (MFA)

Shop Owner logins require a 6-digit OTP verification code step to safeguard administrative capabilities against password spray attacks.

6-Digit OTP MFA

Privacy & Data Governance Note

Customer phone numbers are masked by default (e.g. 0300-***-**45) to ensure customer privacy when managing credit on public shop counter screens.

Course requirement reminder: Hiding UI is not a security control; real enforcement relies on server-side backend rules.
